# GP-095 — «Error al crear la cuenta» en el registro

Urgente del 2026-09-25: un probador con el APK 1.0.0 no podía crear la cuenta.
Todo se comprobó con el **APK de release contra producción** (`api.gymprofit.app`),
en el emulador `Medium_Phone_API_36.1`. Capturas en [`gp095-registro/`](gp095-registro/).

| Commit | Qué |
|---|---|
| `80ce95d` | API · el 400 del registro lleva `USERNAME_EN_USO` o `EMAIL_EN_USO` en `cause` |
| `ed4d4e9` | App · el registro valida como la API y pone cada error en su campo |
| `4774f26` | App · versión 1.0.1 |
| `0feba89` | App · recuperar contraseña usa la misma política (se quedó fuera de `ed4d4e9`) |

## Causa

- Desde `2b5ef1d` (10-07) la API pide una contraseña de 8 a 100 caracteres con
  minúscula, mayúscula, dígito y símbolo. El registro de la app solo pedía 6.
- `RegistroActivity` enseñaba «Error al crear la cuenta» ante **cualquier** fallo de
  `POST /auth/register` —400, red, 429, 5xx— y tiraba el motivo.
- El APK repartido era el de release (no depurable, firmado con la clave de release,
  `BASE_URL` de producción): no era el caso del APK de depuración apuntando a la API local.

Reproducido antes de tocar nada: con la 1.0.0 y `gymprofit1`, «Error al crear la
cuenta»; por `curl`, `400 { password = La contraseña debe incluir minúscula,
mayúscula, dígito y símbolo }` ([antes y después](gp095-registro/antes-despues.jpg)).

## Arreglo

- **API, aditivo.** Mismo 400 y mismo mensaje, más un código estable en `cause`, como
  `CUENTA_DESACTIVADA` (GP-083). Las builds repartidas no notan nada. DEC-028 ya acepta
  que el registro diga si el usuario o el correo existen. `RegistroDuplicadoTest`, con
  el contexto levantado: usuario en uso, correo en uso, los dos (manda el usuario),
  contraseña débil sin código y alta libre.
- **App.** `PoliticaCuenta` es la única copia de las reglas de `RegisterDTO`: contraseña
  de 8 a 100 con `[a-z]`, `[A-Z]`, `[0-9]` y símbolo; usuario de 3 a 50; correo de hasta
  100. `[0-9]` y no `\d`: en Android `\d` acepta dígitos de otras escrituras que la API
  rechaza. La usan el registro y recuperar contraseña. `PoliticaCuentaTest` (11 casos)
  dio **8 fallos** contra la regla anterior del registro.
- **Pantalla.** Requisitos como texto de ayuda antes de escribir; cada error en su campo
  (`setError`) y todos a la vez; usuario o correo en uso en su campo por el código; sin
  código, «Ese usuario o ese correo ya tienen una cuenta»; red, 429 y 5xx por
  `UiFeedback.toastError`; diálogo de carga mientras se envía. Fuera
  `registro_password_corta` y `registro_error`.

API: 585 tests en verde. App: 78.

## Comprobación contra producción (1.0.1 de release)

| Caso | Resultado |
|---|---|
| Contraseña débil (`gymprofit1`) | Error en el campo, sin diálogo de carga ni llamada |
| Usuario en uso | «Ese nombre de usuario ya está cogido» en Usuario |
| Correo en uso | «Ya hay una cuenta con este correo» en Email |
| Sin red | Aviso común de `UiFeedback` |
| Alta válida con usuario `prueba-gp095 josé` (espacio y tilde) | Onboarding completo → Inicio; Perfil, Logros y Récords (vacío) cargan |
| Mismo recorrido con el APK final, tras `0feba89` | Igual |
| Actualizar encima de la 1.0.0 | `adb install -r` sin desinstalar: misma clave |

## Entrega

`GymProFit-1.0.1.apk` (versionCode 10001) en el escritorio del propietario. Firmado con
el mismo certificado que la 1.0.0 (SHA-256 `91d141c2…d722fd`): se instala encima, sin
desinstalar.

## Queda

- El 429 del registro sale con el aviso genérico «Algo salió mal, inténtalo de nuevo»,
  que invita a reintentar enseguida. `UiFeedback` no tiene un mensaje para el 429.
- Que la contraseña se envíe recortada (`trim`) viene de antes y no se ha tocado: el
  login recorta igual.
