## GP-129

**Antes.** Al entrar, `PerfilRemoto.alEntrar` recibía el perfil entero y solo guardaba el sexo,
la actividad y el nombre. Tras borrar los datos de la app, Inicio calculaba con 70 kg, 170 cm y
25 años aunque la API tenía los reales.

**Ahora.** El mismo cruce que GP-111, con cinco campos más. Por campo: lo que trae la API pisa lo
del móvil; lo que no trae, si el perfil del móvil es de esta cuenta y la clave existe, se sube
una vez. Si algo cambia en el móvil, se recalcula el objetivo nutricional guardado
(`DiaNutricion.objetivo`) antes de que Inicio lo pinte.

- **Por qué subir.** Si falla el PATCH del onboarding, la app lo da por guardado en local y la API
  se queda sin nada, sin reintento. Ahora el reintento es la próxima entrada.
- **Lo que esta build no entiende se deja estar**: un objetivo o un nivel nuevos, o un número
  fuera de los rangos del onboarding (peso 30–300 kg, altura 100–250 cm, edad 10–120). Ni se
  guarda en el móvil ni se pisa en la API con lo del móvil. Una altura en metros cae aquí.
- **Nunca un valor por defecto.** El onboarding guardaba el 70, el 170 y el 25 del cálculo cuando
  el campo se había dejado en blanco (la edad es opcional), y esa clave habría contado como
  elegida y se habría subido. Ahora guarda solo lo contestado (`PerfilCuenta.guardarOpcional`);
  el cálculo usa los mismos valores por defecto que antes.
- **Dos cuentas en el mismo móvil.** Los getters de estos cinco campos devuelven el valor por
  defecto si lo guardado es de la otra cuenta, como ya hacían el sexo y la actividad. Si la API
  trae algo y el perfil local era de otra, lo que la API no tiene se tira del móvil.
- En el modelo de la app la altura y la edad son primitivos, así que un `null` de la API llega
  como 0; un 0 se lee como «no lo tiene» (`PerfilCuenta.deUsuario`, con su test).

**Comprobado en el emulador** contra la API local:

1. Instalación limpia y login de `gp111a`: Inicio da **2 277 kcal** a la primera, lo mismo que
   calculó su onboarding.
2. Con esos cinco campos a `NULL` en la base y el móvil con ellos: al arrancar, una PATCH de 97
   bytes y la base vuelve a tenerlos; el arranque siguiente, ninguna.
3. Cerrar sesión y entrar con `gp111b` (en la API tiene objetivo y nivel, pero no peso, altura ni
   edad): el peso, la altura y la edad de `gp111a` desaparecen del móvil, a la API de `gp111b` no
   llega nada, e Inicio calcula con los valores por defecto. Volver a `gp111a`: otra vez 2 277.
